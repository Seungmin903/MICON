1. 개정 목적

기존 Notion 명세의 기능 요구사항과 현재 Figma 화면을 하나의 구현 기준으로 통합한다. 중복된 요구사항 ID를 정리하고, 디자인에만 존재하던 화면 상태와 최근 결정사항을 명시한다.

1.1 이번 개정에서 확정한 사항

  • MVP의 기본 플랫폼은 Android 모바일 앱이다.
  • 알림 기능과 알림 권한은 MVP에서 제외한다.
  • 런타임에 사용자에게 요청하는 필수 권한은 마이크 권한 하나로 제한한다.
  • 첫 음성 온보딩은 기기 음역 측정 → 곡 검색·선택 → MR·가사 기반 음색 녹음 → 부분 리포트 → 선택 저장 순서로 진행한다.
  • 음역은 기존 v7 규칙으로 기기에서 분석한다. 음색 녹음은 BE를 통해 AI에 전달하며 FE가 AI를 직접 호출하지 않는다.
  • 음색 측정곡은 검색하여 선택한다. MR과 가사를 제공하며 MR 시작 위치는 처음부터, 2절부터, 하이라이트부터 중 선택한다.
  • 녹음은 일정 시간이 지났다는 이유로 자동 종료하지 않는다. MR 재생 중 실제 누적 녹음 시간이 30초 이상이고 MR이 일시정지된 상태에서만 녹음 종료 버튼을 활성화하며, 사용자가 눌러 종료한다.
  • 찜 목록은 단순 목록과 폴더형 세트리스트를 함께 제공한다.
  • 온보딩 화면은 결과 없음, 음역 측정, 곡 선택, 음색 녹음, 분석 중, 부분 결과, 저장 가능, 저장 중, 저장 완료, 재시도 필요 상태를 구분한다. ECAPA·Singer-BYOL의 이름·개별 처리 상태는 화면에 노출하지 않는다.
  • 음역은 최저음부터 최고음까지 연속 범위로 표시하고, 닮은 가수는 ECAPA 결과의 코사인 유사도로 검색하여 표시한다.
  • ECAPA와 Singer-BYOL 처리 결과는 모델별로 독립 보관한다. 사용자가 저장하면 최신 프로필 1개를 반영한다.
  • 온보딩 원음은 재시도용으로 최대 1시간 임시 보관하고, 미저장 분석 결과는 마지막 결과 생성 후 24시간 보관한다. 프로필 저장은 원음 장기 보관을 의미하지 않는다.
  • 넓은 저장공간 권한은 사용하지 않는다. 파일을 가져오거나 내보낼 때 Android 시스템 파일 선택기를 사용한다.
  • 백그라운드 녹음은 MVP에서 지원하지 않는다.

2. 서비스 개요

MICON은 사용자의 음역과 보컬 특성을 분석하여 부르기 적합한 노래와 추천 키를 제공하고, 선택한 곡을 실시간 음정 피드백과 함께 연습할 수 있도록 돕는 모바일 서비스다.

3. 서비스 목표

  1. 사용자가 노래를 부르기 전에 자신의 음역에 적합한 곡인지 판단하게 한다.
  2. 반복적인 키 조절 시행착오를 줄이고 적절한 시작 키를 제안한다.
  3. 기존에 부르던 곡 외에도 사용자의 목소리에 맞는 새로운 곡을 발견하게 한다.
  4. 연습 전 예상 난관과 연습 후 개선 구간을 연결해 반복 연습을 돕는다.
  5. 측정 및 연습 기록을 바탕으로 보컬 능력의 변화를 확인하게 한다.

4. 사용자와 이용 범위

4.1 회원

  • 분석 결과, 찜, 세트리스트, 연습 기록을 저장하고 다시 조회한다.
  • 음역·음색 기반 개인화 추천과 추천 키를 받는다.
  • 개인정보와 음성 데이터의 저장·삭제 방식을 관리한다.

4.2 로그인 필수 정책

※ 모든 핵심 기능은 로그인 후 이용할 수 있습니다.

  • 비로그인 사용자는 랜딩, 서비스 소개, 회원가입 및 로그인 화면에만 접근할 수 있다.
  • 음성 측정·분석, 노래 추천·연습, 찜·세트리스트, 기록 및 설정을 이용하려면 반드시 로그인해야 한다.

  • 로그인 완료 후에는 사용자가 접근하려던 화면이나 작업을 이어서 진행할 수 있다.

6. 핵심 사용자 흐름

6.1 첫 분석 흐름

로그인·회원가입 → 기존 선호 가수·장르 조사 → 분석 시작 → 마이크 안내 및 권한 요청 → 기기 음역 측정·결과 전송 → 곡 검색·선택 → MR·가사 로드 → 시작 위치 선택 → MR 재생과 음색 녹음 → MR 재생 중 누적 녹음 30초 이상 확보 → MR 일시정지 → 사용자가 녹음 종료 선택 → BE 업로드·AI 분석 → 부분 리포트 → 필수 결과 완료 → 사용자 선택 저장

  • 기존 회원은 저장된 선호 정보를 재사용한다. 선호 설문 완료와 음성 프로필 저장 완료는 별도로 관리한다.
  • 음역 결과 전송이 끝나기 전에도 곡 선택과 음색 녹음을 진행할 수 있으며, 두 결과를 같은 분석 세션에 연결한다.
  • 종료 조건을 충족하지 못하면 MR을 재개하여 계속 녹음하거나 재녹음·취소할 수 있다. 조건 충족이나 MR 곡 재생 종료만으로 녹음을 제출하지 않는다.
  • 음색 녹음 종료 후 업로드·분석·검색 시간이 필요하다. 음역과 닮은 가수는 준비되는 대로 먼저 표시하고, 저장 가능 여부를 별도로 안내한다.
  • ECAPA·Singer-BYOL의 개별 상태는 BE가 내부적으로 관리한다. 사용자는 분석 중, 추가 분석 필요, 저장 준비 중 등 작업을 이해할 수 있는 안내를 받는다.

6.1.1 MR 시작 위치

선택 동작 인수 기준
처음부터 곡의 시작 시점부터 MR 재생 시작 위치와 가사 위치가 일치한다.
2절부터 해당 곡에 등록된 2절 시작 시점부터 재생 검증된 2절 시각을 사용하며 임의의 비율이나 시간으로 추정하지 않는다.
하이라이트부터 해당 곡에 등록된 하이라이트 시작 시점부터 재생 하이라이트 시각과 가사가 일치한다. 후렴이라는 이유만으로 임의 지정하지 않는다.

2절·하이라이트 메타데이터가 없으면 해당 선택지를 비활성화하고 이유를 안내한다. MR 또는 가사를 제공할 수 없는 곡은 음색 측정에 사용할 수 없음을 알리고 다른 곡을 선택하게 한다.

6.1.2 녹음 종료 조건

녹음 종료 활성화 = 녹음 세션 유효 AND MR 재생 중 누적 녹음 시간 >= 30초 AND MR 일시정지 상태

녹음 확보 조건은 같은 녹음에서 MR이 재생 중이고 마이크 녹음도 실제 진행된 시간의 합이 30초 이상인 것이다. 일시정지·버퍼링·마이크 중단 시간은 제외한다. MR의 현재 재생 위치나 곡 탐색으로 건너뛴 시간을 누적 녹음 시간으로 계산하지 않는다. 이 값은 유효 가창 시간이나 모델 분석 성공 여부를 뜻하지 않는다.

녹음 확보 조건 MR 상태 녹음 종료 버튼
누적 30초 미만 재생 중 비활성화. 필요한 녹음 시간 안내
누적 30초 미만 일시정지 비활성화. 이어 녹음하기 안내
누적 30초 이상 재생 중 비활성화. 일시정지 후 종료 안내
누적 30초 이상 일시정지 활성화. 사용자가 눌렀을 때 녹음 종료
  • MR 일시정지는 녹음 완료·제출이 아니다. 일시정지 동안의 대기 시간은 녹음 확보량에 포함하지 않는다.
  • MR을 재개하면 녹음을 이어가고 종료 버튼을 다시 비활성화한다. 일시정지·재개 구간과 곡 재생 위치를 구분해 기록한다.
  • 녹음 확보 조건은 경과 시간만으로 서버 분석 성공을 보장하지 않는다. 서버는 업로드된 실제 입력의 품질을 별도로 검증한다.
  • 30초는 종료를 허용하는 최소 확보량이다. 재생 중 30초에 도달해도 녹음은 계속되며 자동 종료하지 않는다. 최대 녹음 시간·파일 크기는 수동 종료 흐름에 맞춰 15절에서 별도로 확정한다.
  • MR이 끝까지 재생되면 재생기를 일시정지 상태로 전환한다. 누적 녹음이 30초 이상이면 종료 버튼을 활성화하되 사용자가 누르기 전에는 녹음을 정상 완료·제출하지 않는다. 부족하면 이어 녹음할 위치 선택 또는 재녹음을 안내한다.
  • 재녹음이나 다른 곡으로 바꾸면 새 녹음의 누적 시간을 0초부터 계산한다. 선택한 시작 위치에서 남은 MR 길이가 30초보다 짧으면 다른 시작 위치 또는 곡을 선택하도록 안내한다.
  • 취소·권한 회수·마이크 오류·앱 이탈로 중단된 녹음을 정상 완료나 자동 제출로 처리하지 않는다.

모델 규격 모델별 버전, 체크포인트 해시, 전처리 버전, 차원, 정규화 방식
모델 입력 구간 기본 4초 창·2초 간격, 유효 구간 최소 5개·최대 12개를 두 모델에 동일하게 사용. 일시정지·재개로 끊긴 입력을 가로질러 하나의 연속 구간을 만들지 않음
전처리 ECAPA는 창별 RMS 0.1·16 kHz·L2 정규화, Singer-BYOL은 창별 peak 정규화·44.1 kHz·L2 정규화

이 개정에서는 두 모델의 처리 결과를 독립적으로 보관하는 방식을 적용한다. 이를 단일 대표 벡터나 혼합 점수로 축약하여 원래 모델 결과를 대체하지 않는다. 향후 혼합 점수를 도입하면 비교 대상·모델별 점수·가중치·산식 버전을 별도 계약으로 정의해야 하며, 이번 온보딩에서는 생성하지 않는다.

닮은 가수는 ECAPA 결과 벡터와 같은 규격의 가수 벡터를 코사인 유사도로 비교한다. Singer-BYOL 결과나 두 모델 혼합 점수를 이 검색에 사용하지 않는다. 구간별 유사도를 가수별 순위 점수로 집계하는 세부 규칙은 15절에서 확정한다. 검증된 가수 ID가 없는 데이터는 후보에서 제외한다.

모델 차원·체크포인트·전처리 규격이 다르면 결과를 거부한다. 두 모델이 모두 성공하면 사용한 구간 목록이 같아야 한다. 화면의 누적 녹음 30초 조건과 모델의 최소 유효 구간 기준을 구분하며, 30초를 녹음했더라도 무음·잡음·가창 부족이면 분석 자료 부족으로 처리한다.

10.2.3 세션·리포트·저장 프로필

  • 인증된 사용자 소유의 세션 ID, 녹음 ID, 작업 ID, 결과 버전, 생성·결과 갱신·만료 시각.
  • 음역·두 음색 모델·가수 검색의 내부 상태와 오류·재시도 가능 여부. 모델별 상태는 FE 화면에 표시하지 않는다.
  • 일반 리포트에는 음역 프로필, 닮은 가수 ID·이름·이미지·순위·코사인 점수, 공개용 처리 안내, 저장 가능 여부를 제공한다. 모델 출력 벡터 배열은 포함하지 않는다.
  • 저장 작업 ID·상태·실패 사유, 최신 프로필 ID·버전·저장 시각, 모델별 데이터 참조. 조회 가능한 저장 프로필은 사용자당 1개다.
  • MySQL에는 리포트·메타데이터·벡터 참조를, Vector DB에는 모델별 벡터를 저장한다. 새 데이터가 모두 준비된 후 최신 프로필을 교체한다.
  • 중복 저장은 한 번만 반영한다. 사용자별 저장 순서를 관리하고 저장 중·완료 세션의 분석 결과를 수정하지 않는다.
  • 추천에 인계할 항목은 프로필 ID·버전, 기기 음역 프로필·출처, ECAPA·BYOL 독립 결과 참조·모델 규격, 기존 선호 가수·장르다. 온보딩 저장으로 추천 생성 이벤트를 자동 발행하지 않는다.

곡 검색과 MR·가사 제공은 음색 측정 입력을 위한 기능이다. 추천 AI 실행·추천 결과 저장·추천 알고리즘 변경, 종합 보컬 그래프·BYOL 설명 점수, 저장 리포트 이력·성장 기록은 이번 온보딩 작업에 포함하지 않는다. 서비스 전체의 추천·연습 요구사항은 해당 기능 범위에서 수행한다.

Vector DB 제품 선정·배포, 전체 음원 적재와 새 모델 학습은 별도 작업이다. 온보딩 완료에는 측정에 사용할 MR·가사·시작 구간 데이터와 검증된 가수 ID·동일 ECAPA 규격의 검색 데이터가 필요하다.

14. 전체 인수 조건

  1. 기기 음역 측정 결과의 최저음·최고음을 확인하고 그 사이를 연속 범위로 볼 수 있다.
  2. 측정하지 못한 항목은 낮은 점수가 아닌 미측정 또는 재측정 필요로 표시된다.
  3. 분석 완료 회원에게 음역 기반 추천과 추천 키가 제공된다.
  4. 추천곡을 선택하면 곡 상세, 추천 사유 및 적합도 정보가 함께 변경된다.
  5. 사용자가 확정한 키가 반주와 목표 음정에 동일하게 적용된다.
  6. 현재 가사와 사용자 음정이 연습 진행에 맞춰 표시된다.
  7. 연습 종료 후 구간별 결과를 확인하고 취약 구간을 다시 연습할 수 있다.
  8. 찜한 곡을 조회하고 세트리스트에 분류할 수 있다.
  9. 설정에서 마이크 상태와 원본 녹음 저장 여부를 확인하고 음성 데이터를 삭제할 수 있다.
  10. 앱 어디에서도 알림 권한을 요청하거나 알림 설정을 표시하지 않는다.

14.1 음성 온보딩 인수 조건

  1. 곡을 검색·선택하면 해당 MR과 가사가 제공되며, 처음·2절·하이라이트의 시작 위치와 가사 위치가 일치한다. 누락된 구간은 임의로 생성하지 않는다.
  2. 누적 녹음 29.9초에서 MR을 일시정지하면 종료 버튼이 비활성이고, 30.0초 이상에서 일시정지하면 활성화된다. 30초 이상이어도 재생 중이면 비활성이며 재개하면 다시 비활성화된다.
  3. 재생 중 20초 녹음 후 10초 일시정지하고 다시 10초 녹음하면 누적 확보량은 30초다. 버퍼링·마이크 중단·곡 탐색으로 건너뛴 시간은 합산하지 않는다. 30초 도달·MR 재생 종료만으로 자동 완료·제출하지 않고, 재녹음 시 누적량은 초기화된다.
  4. 음역 결과 전송 중 음색 녹음을 진행해도 같은 세션에 연결된다. 음역은 기기 결과로 표시하며 서버 음역 추론을 호출하지 않는다.
  5. 음역은 최저·최고 사이를 끊지 않고 표시한다. 표시 방식으로 인해 원래 음별 측정 여부·판정값이 변경되지 않는다.
  6. ECAPA가 완료되면 BYOL을 기다리지 않고 가수를 검색한다. 성공한 음역·가수 결과는 먼저 표시하며 ECAPA·BYOL 이름과 개별 상태를 노출하지 않는다.
  7. 닮은 가수는 ECAPA 코사인 유사도로 산출한다. 기본 3명·최대 5명이며 중복 가수·미검증 ID·임의 확률을 표시하지 않는다.
  8. BYOL 등 필수 내부 처리가 실패하면 부분 결과는 유지하고 저장은 비활성화한다. 추가 분석 필요와 재시도를 모델명 없이 안내한다. 가수 검색 실패만 있을 때는 필수 결과가 준비되면 저장할 수 있다.
  9. 두 모델 결과가 독립적으로 저장·조회되고 각각의 차원·체크포인트·전처리 규격을 검증한다. 구간 목록이 다르거나 계약이 불일치하면 거부한다.
  10. 재녹음 후 이전 작업의 결과가 현재 결과에 섞이지 않는다. 앱 재실행 시 유효한 세션은 복구하고, 세션·원음 만료는 각각 새 측정·재녹음으로 안내한다.
  11. 저장 중복 클릭·Vector DB 실패·저장 도중 재시작에도 기존 최신 프로필이 손상되지 않는다. 사용자당 조회 가능한 저장 프로필은 1개이며, 실패 후 새 녹음 없이 다시 저장할 수 있다.
  12. 원음은 최대 1시간, 미저장 결과는 24시간 보관 규칙을 따른다. 삭제·탈퇴 이후 이전 분석·저장 작업이 결과를 복원하지 않는다.
  13. 설문 완료와 음성 프로필 저장 완료가 독립적으로 관리되며 온보딩 저장으로 추천 생성 작업이 자동 실행되지 않는다.

최대 입력 제한과 가수별 구간 점수 집계 규칙은 15절 확정 후 해당 경계값까지 검증한다. 녹음 종료를 위한 누적 30초 기준은 확정이다.

  • 측정용 곡별 2절·하이라이트 시작 시각의 데이터 출처·검수 담당 및 MR·가사 동기화 확인.

  • Android 최소 지원 버전과 테스트 대상 기기
  • 온보딩 외 원본 음성·분석 결과·연습 기록의 정확한 보관 기간. 온보딩 원음 최대 1시간·미저장 결과 24시간은 확정이다.
