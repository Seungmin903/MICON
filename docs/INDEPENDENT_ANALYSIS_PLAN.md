# 독립 분석

음역과 음색 분석을 서로 독립적으로 실행하고, 한 분석의 실패가 다른 분석의 실행과 결과 표시를 막지 않도록 개선하는 계획이다.

## 프론트

- 음역 분석이 실패하거나 진행 중이어도 유효한 노래 녹음이 확보되면 음색 분석을 시작한다.
- 음역과 음색의 진행, 성공, 실패, 재시도 상태를 각각 관리한다.
- 음역 실패 때문에 음색 결과 조회를 중단하거나 성공한 음색을 실패로 처리하지 않는다.
- 음색이 성공했다면 음역 결과가 없어도 리포트에 나와 닮은 가수와 PCA 카드를 표시한다.
- 부분 결과는 계정별로 현재 기기에 임시 보관하고 앱 재실행 시 복원한다.
- 계정이나 측정이 바뀐 뒤 도착한 이전 응답은 무시한다.
- 음역과 음색이 모두 성공하고 서버가 허용한 경우에만 프로필을 저장한다.

## 백엔드

신규 API나 DB 구조 변경 없이 세션 상태 계산을 수정한다.

- 음역 실패가 전체 세션을 무조건 `FAILED`로 덮어쓰지 않도록 한다.
- 분석 하나만 성공하면 `PARTIAL_READY`로 처리한다.
- 음역과 음색이 모두 성공하면 완료 순서와 관계없이 `READY_TO_SAVE`로 처리한다.
- 두 분석 모두 사용할 수 없을 때만 전체 실패 상태로 처리한다.
- 음역과 음색 콜백이 동시에 도착해 상태를 덮어쓰지 않도록 세션 단위 동시성 제어를 적용한다.
- 기존 프로필 저장 조건과 음색 분석 API는 유지한다.

## 검증

- 음역 실패, 음색 성공 상태에서도 음색 분석과 결과 표시가 유지되는지 확인한다.
- 음역 성공, 음색 실패와 양쪽 실패를 검증한다.
- 음역과 음색의 완료 순서를 바꿔도 둘 다 성공하면 프로필을 저장할 수 있는지 확인한다.
- 부분 결과 복원, 중복 요청, 계정 전환, 앱 재실행과 늦은 응답을 검증한다.
- 관련 프론트 및 백엔드 테스트와 Android 디버그 빌드를 실행한다.

## 제외 범위

- 리포트에서 음역만 다시 측정하는 기능
- 기존 음색을 재사용하는 별도 세션이나 API
- DB 구조 변경
- AI 서버와 모델 입력 변경
- ±1반음 기준과 기존 녹음 품질 검사 변경
- 지라 및 MR 업데이트, 서버 배포와 휴대폰 설치
