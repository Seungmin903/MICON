# 아티스트·장르 선호 조사

회원이 아티스트를 먼저 고르고 장르 선택 후 완료한다. 설정에서도 같은 화면으로 수정한다. 선택은 이름이 아닌 기존 `singer_id`, `genre_id`로 저장하며 비회원은 저장 API를 사용할 수 없다.

## 장르 선택지

[MICON 곡 목록](https://docs.google.com/spreadsheets/d/1PBFdZpxraDxvEFwPLOspnhv695z99bPH802t1WSOE98/edit?gid=28353726#gid=28353726)의 `곡 목록` 시트를 2026-09-11에 확인했다. 890행의 앱 song_id는 중복이 없고 대표 가수 표기는 555종이다. 이름 표기 수는 정규화된 가수 수와 다를 수 있다.

2026-09-12 결정: 한국곡은 장르별로 구분하고 일본어곡·영어곡은 각각 하나의 언어 선택지로 묶는다. 가수 국적 대신 곡 언어를 사용하므로 한국 가수가 영어로 부른 곡도 영어곡이다. 원본 태그에는 `K-Pop` 단독 표기 357곡이 있어 한국곡의 발라드·댄스 등을 이 태그만으로 구분하면 안 된다. 한국곡 선택지는 `TJ 차트분류` 열을 참고했으며 한 곡이 여러 차트에 포함될 수 있다.

| 순서 | 화면 표시 | 기존 장르 코드 | 시트 근거 |
|---|---|---|---:|
| 1 | 발라드 | kpop-ballad | 100 |
| 2 | 댄스 | kpop-dance-pop | 100 |
| 3 | R&B/소울 | kpop-rnb-soul | 100 |
| 4 | 록/메탈 | kpop-rock-metal | 100 |
| 5 | 힙합 | kpop-rap-hiphop | 100 |
| 6 | 포크/어쿠스틱 | kpop-folk-acoustic | 100 |
| 7 | OST | etc-ost | 100 |
| 8 | 영어곡 | global-pop | 대표언어 eng 113곡 |
| 9 | 일본곡 | etc-jpop | 대표언어 jpn 105곡 |
| 10 | 트로트 | kpop-adult | 99 |

인디는 원본 자료의 독립된 분류가 없어 포크·록과 구별할 기준을 먼저 마련해야 한다. 재즈는 단독 원본 태그가 2곡이며 레게는 없다. 해당 항목은 초기 설문에서 제외한다. 시안의 임시 이름은 카탈로그에 넣지 않는다.

`V13`은 기존 장르 ID와 원본 이름을 보존하고 `preference_label`, `preference_order`를 추가한다. 곡 수집에서 쓰는 전체 장르와 화면에서 선택 가능한 10개를 구분한다. 기존 저장값은 조회 가능하지만, 새로 저장할 때는 현재 선택지에 있는 장르만 받는다. 편집 화면은 현재 선택지에 남은 기존 선택을 복원한다. 신규 저장은 선택한 전체 집합을 교체한다.

`V15`는 기존 `global-pop`·`etc-jpop` ID를 보존하면서 표시 이름을 `영어곡`·`일본곡`으로 바꾼다. 선호 저장은 계속 같은 장르 ID를 사용하므로 이전 선택이 유지된다. 백엔드는 추천 입력에도 표시 이름을 전달하며 추천 서버는 이전 이름(`팝`, `J-POP`)도 읽을 수 있다.

2026-09-27 추천 규칙 변경: 언어 게이트 대신 운영 DB 장르명 하나로 취향을 판정한다. `영어곡`은 `global-pop`의 `팝`, `일본곡`은 `etc-jpop`의 `J-POP`과 같다. 여러 장르를 선택하면 그 장르들이 동일한 우선순위로 합쳐진다. 알려진 비선호 장르는 ‘새로운 발견’을 포함한 모든 선반에서 제외하고, 장르 미상 곡만 뒤 채움으로 쓴다. `metadata.languages`는 화면 표시용이며 필터로 쓰지 않는다. 운영 DB 확인 시 활성 카탈로그의 국제 장르 중 `global-pop`이 없는 곡은 0건이었다. 향후 그런 곡이 생기면 장르 코드를 카탈로그에 함께 내보내는 방식으로 확장해야 한다. 이 변경은 카탈로그에 없는 곡을 새로 적재하지 않는다.

## 사진과 아티스트 검색

시트의 이미지 종류는 앨범 커버 812개·영상 썸네일 78개로, 가수 프로필 사진이 아니다. [사진 목록과 출처](catalog/artist-portraits.json)에 별도로 검토한 50팀·명의 사진, 저작자, 이용 조건, 별칭을 기록했다. 89개 이름 키에 대응하는 `artist_portrait`은 기존 가수에 결합하며 가수나 곡을 새로 생성하지 않는다. 아직 적재되지 않은 가수도 이후 같은 정규화 이름으로 적재되면 연결된다.

- `/artists`는 활성 상태 곡이 한 곡 이상 연결된 가수만 검색·선택할 수 있다. 확인된 한글·영문 별칭도 검색할 수 있다. 과거에 저장된 비활성 가수 선호는 기존 사용자 설정 화면에서 계속 읽을 수 있지만 새로 선택하거나 저장할 수는 없다.
- 사진이 있는 가수, 등록된 활성 곡 수, 이름, 가수 ID 순으로 정렬한다. 페이지 간 정렬을 고정한다.
- 검토된 사진이 있으면 먼저 사용하고, 없으면 기존 `singer.image_url`을 사용한다.
- 사진이 없거나 로딩이 실패하면 이니셜이 남는다. 사진 여부와 관계없이 선택·저장이 가능하다.
- 사진 출처 버튼에서 저작자·라이선스·원본 링크를 확인할 수 있다. 원형 잘라내기를 안내한다.
- 실제 사진은 HTTPS URL에서 받아 Coil로 표시한다. 외부 서비스 장애 시 이니셜로 표시되며, 향후 자체 저장소로 옮길 때도 출처와 이용 조건을 함께 유지한다.

사진 연결은 기존 가수 ID를 합치지 않는다. 동명이인·그룹/솔로 구분과 데이터 중복 정리는 별도의 카탈로그 작업이다. 사진 목록을 확장할 때는 동명이인 확인 후 출처 자료와 새 Flyway 마이그레이션을 추가한다. 이미 적용된 마이그레이션은 수정하지 않는다.

## API

모든 API는 기존 Bearer 인증을 사용한다.

| API | 동작 |
|---|---|
| GET /genres | 설문 장르 10개를 지정 순서로 반환 |
| GET /artists?query=&page=0&size=30 | 가수 검색·페이지 조회. query 100자, size 1~100 |
| GET /users/me/preferences | 현재 계정의 선택과 완료 상태 복원 |
| PUT /users/me/preferences | 선택 집합 교체. 완료 시 아티스트·장르 각각 1개 이상 |

장르 응답 항목은 `genreId`, `name`, `code`다. 아티스트 항목은 `artistId`, `name`, nullable `imageUrl`, `imageSourceUrl`, `imageAttribution`, `imageLicense`, `imageLicenseUrl`이다. 기존 응답 필드는 유지하며 추가 필드는 선택적으로 읽을 수 있다.

```json
{
  "genreIds": [1, 3],
  "artistIds": [301, 302],
  "onboardingCompleted": true
}
```

위 ID는 요청 형식 예시다. 앱은 API에서 받은 실제 ID를 보낸다. 중복·없는 ID·숨긴 장르·잘못된 개수는 400으로 거부한다. 최대 장르 20개, 아티스트 50명의 기존 계약은 유지한다.

## 화면 상태와 검증

- 원형 3열 선택 카드, 보라색 선택 표시, 아티스트 다음/장르 이전·완료 버튼.
- 탭을 바꾸거나 검색·추가 로드·뒤로 이동해도 선택 유지.
- 기존 임시 저장의 step 의미(0=장르, 1=아티스트)는 보존하고 신규 진입만 아티스트부터 시작.
- 저장 중 조작·중복 완료 방지, 실패 시 선택 유지와 다시 저장, 인증 만료 시 로그인 복귀.
- 설정 수정은 완료 버튼으로 확정하며 음성 프로필 저장 완료와 별개다.

검증 대상은 신규 DB의 10개 장르, 숨긴 장르 거부, 별칭·사진 출처 반환, 사진 없는 가수 저장, 계정 격리, 선택 복원, 검색 응답 순서, 저장 재시도, 작은 화면의 검색과 사진 출처 표시다. `PreferenceSurveyCaptureTest`는 로컬 사진 fixture를 주입하는 명시적인 시각 검증에서만 실행하며 일반 CI에서는 건너뛴다.
