# 키별 반주 운영 전환

기준일: 2026-09-21 KST.

## 완료 결과

| 항목 | 결과 |
|---|---|
| S3 키별 반주 | 5,394개, 22,434,871,017 bytes. 899곡 × 원키를 제외한 6개 변경 키 |
| 팀 배치 결과 | 5,388개. 898곡 × 6개 변경 키 |
| 모나리자 보완 | 6개. Rubber Band 변환, Opus 128kbps, 길이 차이 6ms 검증 |
| DB 등록 | `INSTRUMENTAL_KEY` 5,286행. 881곡 × 6개 변경 키 |
| 운영 카탈로그 | 기존 원키 `INSTRUMENTAL`을 포함해 881곡 모두 `-3..+3` 7키 커버리지 확인 |
| 재실행 결과 | `alreadyExact: 5286` |
| DB 미등록 렌더 | 현재 DB에 없는 18곡은 S3에만 보존. 임의 메타데이터 등록 없음 |

S3 객체 수와 DB 행 수의 차이는 108개로, 현재 DB에 없는 18곡 × 6개 변경 키와 정확히 일치한다. 원키는 기존 `INSTRUMENTAL` 행을 사용하므로 `INSTRUMENTAL_KEY` 개수에 포함하지 않는다.

## 동작 계약

- Android는 `selectedKey=-3..3`을 BE에 전달한다.
- BE는 원키에서 `INSTRUMENTAL`, 변경 키에서 정확히 일치하는 `INSTRUMENTAL_KEY` READY 행을 조회한다.
- 키별 파일이 없으면 다른 키나 원키로 조용히 대체하지 않고 계약된 오류를 반환한다.
- 원본 `instrumental.opus`는 키별 렌더 작업에서 삭제하거나 덮어쓰지 않는다.
- 키 변경은 연습 시작 전에만 허용하며, 재생 중에는 변경하지 않는다.

## 남은 검증

1. 운영 API에서 대표 곡의 `/songs/{songId}/mr?selectedKey=-3..3`을 조회한다.
2. 반환 URL로 실제 오디오를 내려받아 decode와 길이를 확인한다.
3. Android 실기기에서 키 전환 시간, 재생 위치 오차, 재생 중 잠금을 확인한다.
4. 409·422·만료 URL·네트워크 실패 시 사용자 안내와 재시도를 확인한다.

권장 합격 기준은 팀 Wi-Fi에서 키 전환 p95 2.5초 이하, 재생 위치 오차 250ms 이하, 전환 중 판정 프레임 0개다.

## 롤백

1. 신규 Android 배포를 중단하고 직전 정상 소스를 더 높은 `versionCode`로 재배포한다.
2. `registry.py rollback --manifest <검증한-manifest>`로 삭제 대상이 현재 DB의 `INSTRUMENTAL_KEY` 행과 정확히 일치하는지 리허설한다.
3. 검토 후 `--apply`로 manifest에 포함된 `INSTRUMENTAL_KEY` 행만 삭제한다.
4. 원키 연습과 대표 곡 API를 smoke test한다.

S3 객체는 복구와 원인 분석을 위해 유지한다. S3 삭제는 대상 목록·복구 가능성·보존 기간을 별도로 승인한 작업에서만 수행한다.
