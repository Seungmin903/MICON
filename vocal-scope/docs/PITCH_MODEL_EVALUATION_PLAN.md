# VocalScope 음높이 추출 모델 현황 및 비교 평가 계획

## 1. 결론

현재 방식은 CREPE와 Viterbi를 주 음높이 추출기로 유지하고, pYIN을 교차 검증 및 옥타브 보정에 사용하는 구조입니다.

이 구조는 현재 서비스의 기준선으로 유지하는 것이 좋습니다. 이후 SPICE를 독립적인 비교 대상으로 추가하여 CREPE, pYIN, SPICE를 같은 조건에서 평가한 후 실제 서비스 적용 여부를 결정하는 방식이 적절합니다.

현재까지 CREPE와 pYIN의 결과 합의율은 측정되었지만, pYIN, SPICE, CREPE 세 가지를 동일한 조건과 정답 데이터로 비교한 실험은 아직 진행되지 않았습니다.

## 2. 현재 음높이 추출 과정

현재 VocalScope의 음높이 추출 과정은 다음과 같습니다.

```text
보컬 음원
 → CREPE full 확률 계산
 → VAD로 가창 구간 결정
 → Viterbi로 CREPE 음높이 경로 결정
 → pYIN으로 재분석
 → CREPE·pYIN 비교 및 옥타브 보정
 → 튜닝 보정
 → 음표 분절
 → 박자 격자 정렬
```

### 2.1 CREPE full

CREPE full은 분리된 보컬을 10ms 간격으로 분석하고, 각 시점에서 360개 음높이 후보에 대한 확률을 계산합니다.

CREPE가 하나의 음높이를 즉시 결정하는 것은 아닙니다. 이후 Viterbi 알고리즘이 CREPE의 확률을 사용하여 시간적으로 가장 자연스럽게 연결되는 음높이 경로를 선택합니다.

### 2.2 VAD

VAD는 보컬 음량, 원곡 대비 보컬 에너지 비율과 CREPE의 주기성을 종합하여 실제로 노래하는 구간을 결정합니다.

이를 통해 전주, 무음 구간과 보컬 분리 과정에서 남은 반주 소리가 음표로 생성되는 문제를 줄입니다.

### 2.3 Viterbi

Viterbi는 CREPE가 출력한 여러 음높이 후보 가운데 시간 흐름상 가장 자연스럽게 이어지는 음높이를 선택합니다.

현재 구현에서는 torchcrepe의 기본 디코더 대신 자체 Viterbi를 사용하여 과도한 평활화와 배치 경계의 불연속 문제를 줄였습니다.

### 2.4 pYIN

pYIN은 CREPE가 결정한 가창 구간과 추정 음역 주변을 다시 분석합니다.

현재 pYIN은 최종 음높이를 단독으로 결정하지 않습니다. CREPE 결과와의 합의율을 계산하고, CREPE에서 한 옥타브 높거나 낮게 검출된 일부 프레임을 보정하는 용도로 사용됩니다.

따라서 현재 파이프라인에서 pYIN은 CREPE와 경쟁하는 독립 모델이 아니라, CREPE 결과를 확인하는 보조 분석기입니다.

## 3. 현재 구현의 장점

- 모든 피치 곡선을 10ms 프레임 격자로 통일하였습니다.
- CREPE 전체 확률을 한 번만 계산하고 이후 단계에서 재사용합니다.
- VAD가 음높이 분석과 별도로 실제 가창 구간을 결정합니다.
- 자체 Viterbi를 사용하여 연속적인 음높이 경로를 생성합니다.
- pYIN을 CREPE와 성격이 다른 신호처리 기반 검증기로 사용합니다.
- CREPE와 pYIN의 합의율과 옥타브 불일치율을 계산합니다.
- 단계별 처리 시간과 프레임별 디버그 데이터를 저장할 수 있습니다.
- 여러 음원을 일괄 평가할 수 있는 오프라인 평가 도구가 구현되어 있습니다.

## 4. 현재 비교 결과의 의미와 한계

현재 계산되는 `f0AgreementRatio`는 CREPE와 pYIN이 같은 음높이를 출력한 프레임의 비율입니다.

`octaveMismatchRatio`는 두 결과가 약 12반음, 즉 한 옥타브 차이를 보이는 프레임의 비율입니다.

5곡 검증에서는 CREPE와 pYIN의 음높이 합의율이 약 86~91%, 옥타브 불일치율이 약 0.1~1.7%로 측정되었습니다.

그러나 이 결과는 두 방식이 서로 얼마나 일치하는지를 보여주는 지표이며, 어느 방식이 실제 음높이를 더 정확하게 추정했는지는 보여주지 않습니다. 두 방식이 같은 음높이로 잘못 판단하더라도 합의한 것으로 계산되기 때문입니다.

또한 현재 pYIN은 CREPE가 추정한 음역을 기준으로 탐색 범위를 좁혀 실행됩니다. 따라서 pYIN 결과는 CREPE로부터 완전히 독립적이지 않으며, 현재 합의율을 독립적인 모델 비교 결과로 사용할 수 없습니다.

| 항목 | 현재 상태 | 한계 |
|---|---|---|
| CREPE·pYIN 합의율 | 측정 중 | 두 결과가 모두 틀려도 같으면 합의로 처리됩니다. |
| 옥타브 불일치율 | 측정 중 | 정답 음높이를 기준으로 계산한 오류율이 아닙니다. |
| 가창 시작 시점 | 에너지 기준과 비교 | 사람이 표시한 정답 시점이 아닙니다. |
| 공개 악보 비교 | 일부 음표만 비교 | 전체 곡과 전체 프레임에 대한 평가는 아닙니다. |
| 검증 곡 | 5곡 | 가수와 장르가 제한적입니다. |
| SPICE | 미구현 | 현재 비교 결과가 없습니다. |
| 정답 F0 데이터 | 없음 | 모델별 실제 정확도를 계산할 수 없습니다. |

## 5. pYIN·SPICE·CREPE 비교 현황

| 기술 | 종류 | 현재 역할 | 독립 비교 여부 |
|---|---|---|---|
| CREPE full | 딥러닝 피치 추정 모델 | 주 음높이 확률을 생성합니다. | 기준선으로 실행되었습니다. |
| pYIN | 신호처리 기반 피치 추정 알고리즘 | CREPE 결과를 검증하고 옥타브 오류를 보정합니다. | CREPE 의존 범위에서만 실행되었습니다. |
| SPICE | 딥러닝 피치 추정 모델 | 현재 파이프라인에서 사용하지 않습니다. | 아직 실행되지 않았습니다. |

현재 완료된 비교는 CREPE와 pYIN의 프레임별 결과 합의 비교입니다.

SPICE 실행, 세 방식의 동일 조건 비교, 정답 F0 데이터 기반 정확도 평가는 아직 진행되지 않았습니다.

## 6. 권장 진행 방식

### 6.1 현재 방식을 기준선으로 고정

현재의 `CREPE full + Viterbi + pYIN 보정` 결과를 Baseline으로 고정합니다.

현재 코드를 바로 SPICE로 교체하지 않고, 기존 결과와 단계별 처리 시간 및 품질 지표를 보존해야 새로운 방식의 개선 여부를 판단할 수 있습니다.

### 6.2 피치 추출기를 독립적인 구조로 분리

각 피치 추출기가 다음과 같은 공통 형식으로 결과를 반환하도록 구성하는 것이 좋습니다.

```python
{
    "times": [...],
    "midi": [...],
    "voiced": [...],
    "confidence": [...],
    "runtimeSeconds": 0.0,
    "method": "crepe"
}
```

비교 대상 추출기는 다음과 같이 분리합니다.

```text
extract_crepe()
extract_pyin()
extract_spice()
```

비교용 pYIN은 CREPE가 추정한 좁은 음역을 사용하면 안 됩니다. C2~B6와 같은 동일한 공통 음역에서 독립적으로 실행해야 합니다.

SPICE도 CREPE의 VAD와 음역 정보를 사용하지 않고 독립적으로 실행한 후, 결과만 공통 10ms 격자로 변환해야 합니다.

### 6.3 두 종류의 평가를 분리

#### 실험 A: 순수 음높이 정확도

동일한 정답 가창 구간을 각 방식에 적용하고 CREPE, pYIN, SPICE가 추정한 F0만 비교합니다.

이를 통해 유성 판정이나 음표 분절의 영향을 제외하고 각 방식의 순수한 음높이 추정 능력을 확인할 수 있습니다.

#### 실험 B: 실제 서비스 성능

각 방식의 유성 판정과 음높이 결과를 음표 생성 단계까지 연결합니다.

이를 통해 최종 노래방 악보에서 음표의 높이, 시작 시점, 음표 수와 조기 오검출이 어떻게 달라지는지 비교할 수 있습니다.

두 실험을 분리해야 문제가 피치 추출기에서 발생한 것인지, VAD 또는 음표 분절 규칙에서 발생한 것인지 구분할 수 있습니다.

### 6.4 비교할 방식

| 실험 방식 | 목적 |
|---|---|
| CREPE only | CREPE 단독 기준 성능을 확인합니다. |
| pYIN only | 신호처리 기반 방식의 독립 성능을 확인합니다. |
| SPICE only | SPICE 딥러닝 모델의 독립 성능을 확인합니다. |
| CREPE + pYIN | 현재 서비스 방식을 평가합니다. |
| CREPE + SPICE | SPICE가 pYIN보다 좋은 보조 검증기가 될 수 있는지 확인합니다. |

## 7. 권장 평가 지표

| 지표 | 의미 |
|---|---|
| Raw Pitch Accuracy | 정답 음높이와 일정 센트 이내로 일치한 프레임 비율입니다. |
| Raw Chroma Accuracy | 옥타브를 제외하고 음이름이 맞는지 측정합니다. |
| Voicing Recall | 실제 가창 프레임을 얼마나 찾았는지 측정합니다. |
| Voicing False Alarm | 무음 또는 반주를 가창으로 잘못 판단한 비율입니다. |
| Overall Accuracy | 유성 판정과 음높이를 종합하여 전체 프레임 정확도를 측정합니다. |
| Octave Error Rate | 한 옥타브 높거나 낮게 검출한 비율입니다. |
| Note Pitch Accuracy | 생성된 음표의 음높이가 정답 악보와 일치하는 비율입니다. |
| Onset F1 | 음표 시작 시점이 정확한지 측정합니다. |
| 조기 오검출 음표 수 | 전주나 무음 구간에서 생성된 잘못된 음표 수입니다. |
| 처리 시간 | 곡 하나를 분석하는 데 걸리는 시간을 측정합니다. |
| GPU 메모리 | RTX 4050 6GB 환경에서 안정적으로 실행 가능한지 확인합니다. |

## 8. 권장 실행 순서

1. 현재 CREPE·pYIN 파이프라인을 Baseline으로 고정합니다.
2. 평가 코드가 피치 추출기를 선택할 수 있도록 구조를 분리합니다.
3. pYIN을 CREPE와 무관한 전체 음역으로 독립 실행합니다.
4. SPICE를 실제 서비스가 아닌 오프라인 평가 경로에 먼저 추가합니다.
5. 같은 보컬 음원으로 CREPE, pYIN, SPICE를 각각 실행합니다.
6. 정답 F0 또는 사람이 검수한 기준 악보와 비교합니다.
7. 단독 모델과 앙상블 조합의 정확도 및 처리 성능을 비교합니다.
8. 검증 결과가 나온 후 실제 서비스 파이프라인의 변경 여부를 결정합니다.

## 9. 최종 정리

현재 VocalScope의 음높이 추출 파이프라인은 실제 서비스의 기준선으로 사용할 수 있는 상태입니다.

다만 현재 측정된 CREPE·pYIN 합의율은 모델 정확도 비교가 아니라 교차 검증 지표입니다. SPICE까지 포함한 모델 선정 실험이 완료된 것은 아닙니다.

다음 작업의 핵심은 SPICE를 곧바로 서비스에 적용하는 것이 아니라, CREPE, pYIN, SPICE를 독립적으로 실행하고 동일한 정답 데이터와 평가 지표를 사용하여 비교할 수 있는 평가 구조를 만드는 것입니다.
